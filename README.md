# Yandex Station — root / ADB kit (Linux / macOS)

Самодостаточный стенд для получения **root-доступа почти любой** своей Яндекс Станции в собственной домашней сети.

Вектор — eQuasar: локальная подмена `quasar.yandex.net` + сертификат eMudhra,
в ответ на `/get_sync_info` отдаётся `adbd.remoteActivation=true` и колонка
поднимает сетевой ADB на `:5555`.

> ⚠️ Только для **своих** устройств и **своей** сети. Сброс снимает привязку аккаунта,
> неудачная прошивка может превратить колонку в кирпич. Всё на свой риск.

## Что проверено

Проверено на **трёх моделях**:

| Модель | Статус |
|---|---|

| Yandex Mini (`yandexmini`, `1.305.4.16…20250721`) | ✅ работает |
| Yandex Station Midi (`cucumber`, с часами) | ✅ работает |

- **Мини**: даунгрейд проверен до `1.305.4.16.3237824040.20250721` (ставили с `1.3.4.12…`),
  и уже с этой прошивки включается ADB через `/get_sync_info` → `:5555`.

На живой колонке (Лайт 1, прошивка `0.369.1.46.4778262442.20261013.297`, `VERSION` 3.21)
и на Мини (`1.305.4.16.3237824040.20250721`):

```
adb connect <IP>:5555
adb shell id   →  uid=0(root) gid=0(root)
```

- factory-прошивка (`0.52.1.101…PVT.factory`) **принимает** сертификат eMudhra;
- retail-сборки новее (например `0.372.1.8…20261019`) сертификат **отбивают**
  (`TLSV1_ALERT_UNKNOWN_CA`) — на них нужен откат на `20261013`.

## Состав

```
start.sh                     поднять стенд (dnsmasq + HTTPS-прокси на :80/:443)
stop.sh                      остановить
check.sh                     найти колонку в сети, проверить ADB, показать версию
scripts/equasar_server.py    eQuasar-сервер: /get_sync_info, /check_updates, раздача OTA
certs/fullchain.pem          лист quasar.yandex.net + промежуточный eMudhra G3C
certs/quasar-all.key         приватный ключ листа
config/dnsmasq.conf.tpl      шаблон DNS (IP этой машины подставляется в start.sh)
firmware/manifest.json       метаданные прошивки: версия, размер, crc32, sha256
```

Прошивка **не входит** в репозиторий (66 МБ). Нужен файл:

```
0.369.1.46.4778262442.20261013.297.zip   66 814 464 Б
crc32 371630625
sha256 74d4e8fae375b2ad1757761e01caf6be0209d216328ce1a942dbef38c8f20d11
```

Положить в `firmware/` рядом с `manifest.json`.

## Требования

Главное — **роутер, где можно вручную поменять DNS** (или раздать эту машину как DNS по DHCP).
Сама машина со стендом — любая: **Linux-ПК/сервер (Debian, Ubuntu, Arch…) или macOS**.
Железо не важно, подойдёт и старый ноутбук, и мини-ПК, и Raspberry Pi.

- `dnsmasq` (`apt install dnsmasq` / `pacman -S dnsmasq` / `brew install dnsmasq`);
- `python3` (OpenSSL ≥ 1.1.1, т.е. Python 3.8+), `openssl`, `dig`;
- свободные порты **53**, **80**, **443** (на Linux часто занят 53 — отключи
  `systemd-resolved`/`avahi` или настрой их не мешать);
- `adb` в PATH (или свой путь в `check.sh`);
- колонка в той же сети;
- **ФИЗИЧЕСКИЙ** доступ к **своей** колонке.

## Порядок

### 1. Стенд
```bash
./start.sh          # спросит sudo, покажет свой IP и проверку DNS
```

### 2. DNS на роутере
**Настройки → Параметры сети → «Настроить DNS вручную» → DNS1 = IP этой машины.**

Проверка с этой же машины (**подставь IP своего роутера** — `192.168.31.1` только пример):

```bash
# IP роутера: macOS
ROUTER=$(route -n get default | awk '/gateway/{print $2}')
# IP роутера: Linux
ROUTER=$(ip route | awk '/^default/{print $3; exit}')
echo "$ROUTER"

dig +short quasar.yandex.net @$ROUTER    # должен вернуть IP этой машины
```

### 3. Сброс колонки в factory
1. Выдернуть питание и вставить обратно.
2. Когда загорится - зажать **кнопку паузы** (▶/⏸, не микрофон).
3. Держать ~7–10 до желтого/салатового индикатора.
4. Дождаться слова Алисы

### 4. Настройка в приложении
«Дом с Алисой» → добавить устройство → дойти до шага **выбора Wi-Fi** →
убедиться, что DNS уже указывает на эту машину → подключить к своей сети.

### 5. Прошивка (обычно не нужна)
Обновления по умолчанию **выключены** (колонке отдаётся `hasUpdate:false`): стенд
поднимает ADB на той прошивке, что уже стоит. Если нужен откат/установка конкретной
версии — включи раздачу: `touch run/downgrade` и рестарт. Закачка пойдёт
**с этой машины** (66 814 464 Б, ~30–60 с). Питание не трогать. В `log/server.log`:

```
>>> [DOWNGRADE] Колонке отправлен манифест уязвимой прошивки!
>>> [OTA] файл отдан ПОЛНОСТЬЮ (66814464 б)
```

Манифест отдаётся **повторно, пока колонка не на целевой версии** (из имени файла
в `firmware/`) — если с первого раза не зашло, повторить с шага 3.

### 6. ADB
После ребута колонка заберёт `/get_sync_info` и поднимет `:5555`:
```bash
./check.sh
# или
adb connect <IP>:5555 && adb shell id
```

### 7. Убрать стенд
```bash
./stop.sh
```
и вернуть на роутере DNS в «Автоматически».

| Что | Действует до |
|---|---|
| лист `quasar.yandex.net` | **2029-01-22 18:19:09 UTC** |
| промежуточный eMudhra G3C | 2028-12-31 |
| корень AAA Certificate Services | долгоживущий |

Если Яндекс отзовёт набор — колонки начнут отклонять TLS, стенд останется
рабочим только как DNS-прокси без активации ADB.

Ключ `certs/quasar-all.key` — публично известный (из набора eQuasar), но всё равно
не используйте его нигде, кроме своей колонки.

## Настройки через окружение

Всё необязательное — по умолчанию стенд работает «из коробки» без единой переменной.

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `COLUMN_IPS` | **пусто** | Список IP колонок через запятую (`192.168.1.50,192.168.1.51`). Нужен только если автоопределение по User-Agent и device-id не срабатывает. Пустое значение — норма: матчим по `User-Agent: YandexStation` и по id устройства в пути. |
| `COLUMN_ID` | `LP00000000000001982300007d20fe15` | device-id вашей колонки, если она другой модели/ревизии. |
| `LOCAL_IP` | определяется автоматически | IP этой машины, который колонка получит в манифесте (`fallbackIp`). Задавать только если автоопределение выбрало не тот интерфейс (VPN, несколько сетей). |

IP роутера в переменных не нужен — он только для проверки DNS вручную.
Если у вас не `192.168.31.0/24` (например `192.168.1.0/24`, `10.0.0.0/24`),
ничего в файлах менять не надо: `check.sh` сам определит подсеть, а `dig`
подставляй на IP своего роутера.

Примеры:

```bash
# обычный запуск — ничего указывать не нужно
./start.sh

# если у вас несколько колонок и автоопределение не сработало
COLUMN_IPS="192.168.1.50,192.168.1.51" ./start.sh

# если машина смотрит в сеть через не тот интерфейс
LOCAL_IP=192.168.1.10 ./start.sh
```

`check.sh` сам определяет подсеть по маршруту по умолчанию — правки не нужны,
работает в любой сети (`192.168.x.x`, `10.x.x.x`, `172.16.x.x`).

| Симптом | Что смотреть |
|---|---|
| Колонка «нет доступа к интернету» в factory | `log/server.log`: идут ли `HEAD /generate_204 → 204`; DNS на роутере точно на IP этой машины? |

## Sync с ADB (все модели)

`/get_sync_info` собирается **локально** (без проксирования в Яндекс, без 429):
берётся шаблон ответа, из него вырезаются приватные поля и вписывается `adbd`.
Подробно: [docs/sync-adb.md](docs/sync-adb.md)

Если Яндекс всё же ответил `429 Too Many Requests` или `5xx` на любой другой запрос
колонки, этот ответ **не пробрасывается**: колонка получает `200` — для sync-путей
полный конфиг с `adbd.remoteActivation=true`, для остальных `{"status":"ok"}`.
На `429`/`5xx` сервер делает до 3 повторов с паузой 2.5 с и только потом уходит в fallback.

### Обновления выключены по умолчанию

`start.sh` больше **не** запускает `--downgrade`: на `/check_updates` колонка получает
`{"hasUpdate":false}`, а `.zip` не отдаётся вовсе (404). Чтобы вернуть раздачу прошивки:

```bash
touch run/downgrade      # откат/обновление на файл из firmware/
./stop.sh && sudo ./start.sh
```

## Другие модели станций (НЕ ПРОВЕРЕНО)

Стенд не привязан к «Лайт 1» жёстко: меняются всего три вещи — **образ прошивки**,
**версия в сервере** и **строка модели**. Всё остальное (DNS-подмена `quasar.*`,
сертификат eMudhra, логика `/get_sync_info`) одинаковое для всего quasar-семейства,
потому что сертификат покрывает `quasar.yandex.net/.ru`, `*.quasar.yandex.net`,
`scbh.yandex.net`, `uniproxy.alice.yandex.net`, `strm.yandex.ru` и т.д.

### Что подменить

1. **Прошивка** — положить `firmware/<version>.zip` и переписать `firmware/manifest.json`
   (version, filename, size, crc32, sha256).
2. **Сервер** — в `scripts/equasar_server.py` поменять:
   ```python
   OTA_VERSION = "<version>"
   OTA_FILE    = os.path.join(BASE_DIR, "firmware", "<version>.zip")
   ```
   и, если нужно, `DOWNGRADE_PAYLOAD` (version, downloadUrl, crc32, updateId).
3. **Название/модель** — в `README.md` и, при желании, `device_name` в конфиге
   сторонних сервисов.

### Где брать образы

- зеркало: `http://144.76.194.29:62891/<platform>/` — там `metadata.json` с
  `version`, `crc32`, `downloadUrl`, `fallbackIp`;
- официальный CDN: `https://quasar.s3.yandex.net/<platform>/ota/user/<uuid>/<version>.zip`.

Кодовые имена платформ: `yandexmicro` (Лайт 1), `plum` (Лайт 2), `yandexmini`,
`yandexmini_2`, `yandexmidi` (Станция 2), `cucumber` (Миди), `yandexstation`,
`yandexstation_2` (Макс), `chiron` (Дуо Макс) и т.д.

### Важные оговорки

- Это **не тестировалось** на остальных моделях: проверено на `yandexmicro` (Лайт 1,
  `20261013`), `yandexmini` (Мини, `1.305.4.16…20250721`) и `cucumber` (Миди).
- У других моделей другой **boot/разделы** и другая раскладка — образ от чужой
  платформы ставить нельзя, это кирпич.
- На части моделей `get_sync_info` и `activate_adb.sh` могут отличаться по структуре
  конфига; тогда правится `SYNC_INFO_PAYLOAD` под их формат.
- Не все прошивки принимают серт: на новых retail-сборках TLS отбивается
  (`unknown ca`), нужен откат на заведомо «уязвимую» версию.
- Для устройств без `activate_adb.sh` вектор eQuasar не сработает вовсе.

Если проверишь на другой модели — присылай платформу, версию и лог, допишем сюда.
